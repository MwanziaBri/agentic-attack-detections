# What Xalgorix leaves behind

Xalgorix ([xalgorix/xalgorix](https://github.com/xalgorix/xalgorix), formerly `xalgord/xalgorix`, which now redirects; repository created March 13, 2026, first release `v0.2.4` the same day; Apache-2.0; 1,387 stars and 289 forks on November 23, 2026; reviewed at `f5b1a99a`, one commit after `v4.6.205`, November 23, 2026) is a single Go binary with an embedded React dashboard. An AI agent works through a penetration test plan against a web application or API with a shell, a headless browser and an HTTP client, a second agent re-exploits each finding, and the result is a PDF report. The same engine is sold as a hosted service at xalgorix.com. The Docker image has more than 71,000 pulls. File references are to the repository at `f5b1a99a`.

**Fragility** says what it takes to remove a signal: *code* means editing Xalgorix, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string that is an example in the system prompt: removing it means editing Xalgorix, but the model can also change it on any run, so treat it as likely, not certain.

## An exposed Xalgorix console

The dashboard is a single-page app, so the HTML is the same shell on every path. A console bound to a public address has auth switched on (the binary will not bind publicly without it), so what a scanner sees is the shell and the unauthenticated endpoints. The exception is a loopback install published through a reverse proxy: there `/api/auth/status` returns `{"auth_enabled":false,"authenticated":true}` and the API is open (`internal/web/auth_session.go:381-385,555-572`).

## What the code does not contain

Xalgorix ships no implant, C2 listener, webshell manager or persistence code, and nothing that runs on a victim host. The callback listener only records inbound requests. Its agents use the shell, the browser and whatever tools are installed, and the Docker image includes Kali's exploitation, password and post-exploitation tool groups, so what happens after a finding depends on the model and the operator's instruction. Results stay on the operator's disk; there is no telemetry and no upload to the vendor in the self-hosted build. The built-in target block covers the operator's own machine, loopback and private ranges only: there is no allow list of authorized domains beyond what the operator types in.
